Descripcion detallada de la carpeta lexer

1. Proposito general

La carpeta src/lexer contiene el analizador lexico de pseudoWeb. Su trabajo es convertir el codigo fuente en una secuencia de tokens que luego consume el parser.

La implementacion actual esta dividida en un orquestador central, scanners especializados, tipos compartidos y utilidades de caracteres. Esa separacion mantiene la tokenizacion pequena, testeable y facil de extender.

3. Descripcion de los modulos

3.1 orchestrator/lexer.ts

Este archivo contiene la clase Lexer. Es el punto de entrada del modulo y coordina el recorrido del texto fuente.

Responsabilidades principales:

- Recibir el codigo fuente en el constructor.
- Iterar caracter por caracter hasta llegar al final.
- Ignorar espacios, retornos de carro y tabulaciones.
- Emitir tokens de salto de linea cuando aparece \n.
- Delegar el reconocimiento a los scanners especializados.
- Agregar el token EOF al terminar.

3.2 orchestrator/lexerState.ts

Este archivo implementa el estado interno del lexer. Guarda la posicion actual, el inicio del lexema, la linea, la columna y el arreglo de tokens generados.

Responsabilidades principales:

- Avanzar por el codigo fuente.
- Consultar el caracter actual y el siguiente.
- Marcar el inicio de cada lexema.
- Construir tokens con tipo, lexema, literal y ubicacion.
- Exponer el arreglo final de tokens.

3.3 orchestrator/lexerContext.ts

Define el contrato que consumen los scanners. Esto evita que dependan directamente de la implementacion concreta del estado.

Metodos clave:

- markStart()
- peek()
- peekNext()
- advance()
- isAtEnd()
- addToken()
- sliceLexeme()

3.4 scanners/numberScanner.ts

Reconoce numeros enteros y reales.

Comportamiento actual:

- Lee digitos consecutivos.
- Si encuentra un punto seguido de otro digito, lo interpreta como numero real.
- Convierte el literal a numero nativo antes de emitir el token.
- No implementa notacion cientifica en la version actual.

3.5 scanners/stringScanner.ts

Reconoce literales entre comillas simples o dobles.

Comportamiento actual:

- Soporta escapes como \n, \t, \r, \\\, \" y \'
- Lanza error si la cadena no cierra.
- Emite el valor ya procesado como literal.
- La implementacion actual distingue entre comillas dobles y simples para el tipo del token.

3.6 scanners/identifierScanner.ts

Reconoce identificadores y palabras reservadas.

Comportamiento actual:

- Lee letras, digitos y guion bajo.
- Resuelve palabras reservadas mediante tokenRules.ts.
- Trata DIV y MOD en mayusculas como operadores especiales.
- Trata div y mod en minusculas como identificadores normales.

3.7 scanners/operatorScanner.ts

Reconoce operadores y delimitadores puntuales.

Comportamiento actual:

- Soporta :=, **, <=, >=, <>, ..
- Emite operadores de un caracter como +, -, *, /, =, < y >.
- Emite delimitadores como parentesis, coma, punto y coma y dos puntos.
- Lanza LexerError si encuentra un caracter no soportado.

3.8 scanners/commentScanner.ts

Descarta comentarios sin producir tokens.

Comportamiento actual:

- skipLineComment consume hasta antes del salto de linea.
- skipBlockComment consume comentarios entre /* y */.
- Los comentarios anidados no forman parte del comportamiento actual.

3.9 types/tokenType.ts

Define la enumeracion TokenType. Contiene palabras clave, operadores, delimitadores, tipos de dato, identificadores y tokens especiales.

Tokens relevantes en la implementacion actual:

- Accion, FinAccion, Ambiente, Proceso, Funcion, FinFuncion, Procedimiento, FinProcedimiento
- Si, SiNo, FinSi, Mientras, FinMientras, Para, FinPara, Repetir, Hasta, HastaQue, Segun, Hacer, Otro, FinSegun
- Leer, Escribir, Entonces, ES, Verdadero, Falso, Y, O, No
- Asignacion, Suma, Resta, Multiplicacion, Division, Div, Mod, Potencia
- Igual, Distinto, Menor, Mayor, MenorIgual, MayorIgual
- ParentesisIzquierdo, ParentesisDerecho, DosPuntos, Coma, Rango, PuntoYComa, SaltoDeLinea, EOF

3.10 types/token.ts

Define la estructura comun de un token.

Campos:

- type: clasificacion del token.
- lexeme: texto original leido del codigo fuente.
- literal: valor interpretado.
- line: linea donde se registro el token.
- column: columna donde se registro el token.

3.11 types/tokenRules.ts

Centraliza las palabras reservadas y la resolucion de identificadores.

Reglas relevantes:

- El mapa KEYWORDS resuelve palabras reservadas en minusculas.
- resolveIdentifierType convierte DIV y MOD exactos en sus operadores correspondientes.
- Cualquier otro lexema cae en Identificador.

3.12 types/scannerContext.ts

Reexporta el contrato que usan los scanners desde el contexto del lexer.

3.13 types/lexerError.ts

Define el error especializado que utiliza el lexer para reportar caracteres no soportados, cadenas sin cerrar y comentarios incompletos.

3.14 utils/charUtils.ts

Agrupa utilidades pequenas para clasificar caracteres.

Funciones actuales:

- isDigit(char)
- isAlpha(char)
- isAlphaNumeric(char)

4. Flujo de tokenizacion

El flujo actual es simple:

1. Lexer.tokenize() marca el inicio de cada lexema.
2. scanToken() inspecciona el caracter actual.
3. Segun el caracter, delega a un scanner especializado o emite un token simple.
4. Los espacios y tabulaciones se omiten.
5. Los saltos de linea se convierten en token SaltoDeLinea.
6. Al finalizar, se agrega EOF.

5. Observaciones de arquitectura

- El orquestador contiene la logica de control del flujo.
- Los scanners encapsulan la logica de reconocimiento.
- tokenRules.ts concentra las reglas especiales para palabras reservadas.
- Las utilidades de caracteres mantienen el codigo de reconocimiento pequeño y reutilizable.

6. Nota sobre tipos y errores

El enum incluye algunos valores adicionales para uso interno o futuro, pero el flujo actual no los emite de forma normal. Los errores se propagan mediante LexerError con ubicacion concreta para facilitar diagnostico en parser y tests.
