Descripcion detallada de la carpeta lexer

1. Proposito general

La carpeta src/lexer contiene el analizador léxico (lexer) del lenguaje pseudoWeb dentro del paquete core.
Su responsabilidad es transformar el código fuente en una secuencia de tokens que el parser puede analizar.

El lexer es la primera etapa del compilador: examina caracteres uno a uno, reconoce patrones
(palabras clave, identificadores, operadores, números, cadenas), genera tokens con tipo y contexto
(línea, columna), y descarta componentes no sintácticos (espacios, comentarios).

En lugar de un único archivo monolítico, el código está organizado en scanners especializados
para cada categoría de token (números, cadenas, identificadores, operadores, comentarios)
y utilidades para manejo de caracteres.

2. Estructura general de la carpeta

lexer/
  lexer.ts
  tokenTypes.ts
  tokenRules.ts
  scanners/
    numberScanner.ts
    stringScanner.ts
    identifierScanner.ts
    operatorScanner.ts
    commentScanner.ts
  utils/
    charUtils.ts

3. Descripcion archivo por archivo

3.1 lexer.ts

Este es el archivo principal del módulo lexer. Contiene la clase Lexer que orquesta todo el proceso
de análisis léxico.

Responsabilidades principales:

- Recibir el código fuente como string en el constructor.
- Mantener la posición actual (start, current), línea y columna para reportar ubicaciones.
- Iterar caracteres del código fuente invocando scanToken() para cada nuevo token.
- Delegar a scanners especializados para reconocer cada tipo de token.
- Manejar separadores no sintácticos: espacios, tabulaciones, retornos de carro, saltos de línea.
- Acumular tokens generados en un array.
- Agregar token EOF al final.

Métodos principales:

- constructor(source: string): Inicializar con el código fuente.
- tokenize(): Punto de entrada; itera el código y retorna array de tokens.
- scanToken(): Llamada para cada nuevo token. Examina el carácter actual y delega.
- peek(): Retorna el carácter en current sin avanzar.
- peekNext(): Retorna el carácter en current+1 sin avanzar.
- advance(): Incrementa current, maneja saltos de línea para actualizar línea/columna.
- addToken(): Agrega token al array con información de ubicación.
- isAtEnd(): Verifica si se alcanzó el final del código.

3.2 tokenTypes.ts

Este archivo define la enumeración TokenType con todos los tipos de tokens que el lexer puede generar.

Categorías de tokens:

a) Palabras clave (Keywords):
   - Accion, FinAccion: Delimitadores de la acción principal.
   - Ambiente: Delimitador del bloque de declaraciones.
   - Proceso: Delimitador del bloque de sentencias.
   - Funcion, FinFuncion: Delimitadores de funciones.
   - Procedimiento, FinProcedimiento: Delimitadores de procedimientos.
   - Si, Entonces, SiNo, FinSi: Estructura de decisión if-then-else.
   - Mientras, Hacer, FinMientras: Estructura de iteración while.
   - Para, Hasta, FinPara: Estructura de iteración for.
   - Repetir, HastaQue: Estructura de iteración repeat-until.
   - Segun, Caso, Otro, FinSegun: Estructura de selección switch.
   - Leer, Escribir: Sentencias de entrada/salida.
   - Y, O, No: Operadores lógicos.
   - Const: Declarador de constante.
   - Retornar: Retorno de función.
   - Div, Mod: Operadores de división entera y residuo.
   - Verdadero, Falso: Literales booleanos.
   - Entero, Real, Caracter, Alfanumerico, Logico: Tipos de datos.

b) Literales:
   - Number: Número (entero o real).
   - String: Cadena de caracteres entre comillas.
   - Identifier: Nombre de variable, función, procedimiento, constante.

c) Operadores:
   - Asignacion: :=
   - Igual: =
   - Distinto: <>
   - Menor: <
   - Mayor: >
   - MenorIgual: <=
   - MayorIgual: >=
   - Suma: +
   - Resta: -
   - Multiplicacion: *
   - Division: /
   - Potencia: **
   - Modulo: %

d) Delimitadores:
   - ParenIzq, ParenDer: ( )
   - CorcheteIzq, CorcheteDer: [ ]
   - LlaveIzq, LlaveDer: { }
   - Coma: ,
   - PuntoYComa: ;
   - TiempoDosPuntos: :
   - Punto: .

e) Especiales:
   - SaltoDeLinea: Salto de línea \n.
   - EOF: Fin de archivo.
   - Error: Token de error (nunca generado en uso normal).

3.3 tokenRules.ts

Este archivo centraliza la información de palabras clave y reglas especiales de tokens.

Responsabilidades principales:

- Mantener un mapa de palabras clave reservadas a su TokenType correspondiente.
- Definir reglas para tokens especiales (como DIV, MOD en mayúsculas para operadores vs identificadores).
- Proporcionar funciones auxiliares para consultar si una palabra es reservada.

Contenido:

- KEYWORDS: Map que asocia strings como "Accion", "Ambiente", "Si" a su TokenType.
- isKeyword(word: string): Verifica si una palabra es reservada.
- getKeywordType(word: string): Retorna el TokenType de una palabra reservada.
- Reglas especiales:
  - DIV (en mayúsculas) es el operador de división entera.
  - MOD (en mayúsculas) es el operador de residuo.
  - Si están en minúsculas, se tratan como identificadores.

3.4 scanners/ (subdirectorio)

Este subdirectorio contiene scanners especializados, cada uno responsable de reconocer
una categoría específica de token y acumular caracteres hasta formar el token completo.

3.4.1 scanners/numberScanner.ts

Este scanner reconoce y crea tokens de números.

Responsabilidades principales:

- scanNumberToken(state): Acumula dígitos para formar un número.
- Determina si el número es entero o real (basándose en la presencia de un punto).
- Maneja números de la forma:
  - Enteros: 42, 1000
  - Reales: 3.14, 2.0
  - Notación científica (si está soportada): 1e10, 1.5e-5
- Retorna Token con type Number y literal como número nativo.

Parámetro state (LexerState):

El scanner recibe un objeto state que proporciona:
- isAtEnd(): Verifica si se alcanzó el final del código.
- peek(): Carácter actual.
- peekNext(): Carácter siguiente.
- advance(): Avanzar un carácter.

Este patrón de inyección es consistente en todos los scanners.

3.4.2 scanners/stringScanner.ts

Este scanner reconoce y crea tokens de cadenas de caracteres.

Responsabilidades principales:

- scanStringToken(state, quoteChar): Acumula caracteres entre comillas.
- Maneja escape sequences como \", \\, \n, etc.
- Detecta si la cadena no cierra correctamente (error).
- Retorna Token con type String y literal como valor de la cadena.

Soporta:

- Cadenas simples: "Hola"
- Cadenas con espacios: "Hola Mundo"
- Cadenas con escapes: "Hola\nMundo"
- Carácter de comilla: quoteChar (generalmente ").

3.4.3 scanners/identifierScanner.ts

Este scanner reconoce y crea tokens de identificadores y palabras clave.

Responsabilidades principales:

- scanIdentifierToken(state): Acumula caracteres alfanuméricos y guiones bajos.
- Verifica si el identificador es una palabra clave reservada.
- Si es palabra clave, retorna Token con el TokenType correspondiente.
- Si es identificador, retorna Token con type Identifier.
- Maneja especial: DIV y MOD (en mayúsculas) como operadores, en minúsculas como identificadores.

Reglas de identificador:

- Comienza con letra o guion bajo.
- Continúa con letras, dígitos o guiones bajos.
- No puede ser palabra clave reservada (excepto DIV/MOD con capitalización específica).

3.4.4 scanners/operatorScanner.ts

Este scanner reconoce y crea tokens de operadores.

Responsabilidades principales:

- scanOperatorToken(state): Examina el carácter actual y posiblemente el siguiente.
- Construye operadores de dos caracteres: :=, <>, <=, >=, **.
- Construye operadores de un carácter: =, <, >, +, -, *, /, %.
- Maneja especiales como parentesis, corchetes, llaves, coma, punto, punto y coma, etc.
- Retorna Token con el TokenType correspondiente.

Operadores soportados:

- Asignacion: :=
- Relacionales: =, <>, <, >, <=, >=
- Aritméticos: +, -, *, /, **
- Especiales: %, (unario), ), [, ], {, }, ,, ;, :, .

3.4.5 scanners/commentScanner.ts

Este scanner ignora comentarios y ajusta la posición del lexer.

Responsabilidades principales:

- skipBlockComment(state): Descarta un comentario de bloque /* ... */.
- skipLineComment(state): Descarta un comentario de línea // ...
- Actualiza información de línea/columna durante el descarte.
- No genera tokens; simplemente avanza el state.

Tipos de comentarios soportados:

- Comentarios de línea: // Este es un comentario
- Comentarios de bloque: /* Este es un comentario de bloque */
  - Anidamiento de bloques: /* /* anidado */ */ (si está soportado)

3.5 utils/charUtils.ts

Este archivo proporciona utilidades para clasificación y manejo de caracteres.

Responsabilidades principales:

- isAlpha(char): Verifica si el carácter es una letra (a-z, A-Z, _).
- isDigit(char): Verifica si el carácter es un dígito (0-9).
- isAlphaNumeric(char): Verifica si es letra o dígito.
- isWhitespace(char): Verifica si es espacio, tabulación, etc.
- isOperatorChar(char): Verifica si puede ser parte de un operador.

Funciones auxiliares adicionales según sea necesario para scanners.

4. Flujo de tokenizacion

El flujo típico de tokenización es:

1. Lexer.tokenize() es invocado con el código fuente.
2. Se inicializa un array vacío para acumular tokens.
3. Se itera mientras no sea fin de código:
   a. scanToken() examina el carácter actual.
   b. Si es espacio/tab: avanza sin generar token.
   c. Si es salto de línea: genera token SaltoDeLinea.
   d. Si es comentario: skipBlockComment o skipLineComment descarta caracteres.
   e. Si es dígito: numberScanner acumula y genera Number.
   f. Si es comilla: stringScanner acumula y genera String.
   g. Si es letra/guion bajo: identifierScanner acumula y verifica palabra clave.
   h. Si es operador: operatorScanner genera token de operador.
4. Después de iterar completamente, se agrega token EOF.
5. Se retorna el array de tokens.

5. Manejo de ubicacion (linea y columna)

El lexer mantiene información de ubicación para cada token:

- line: Número de línea (comienza en 1).
- column: Número de columna en esa línea (comienza en 1).

Actualización durante avance:

- advance() incrementa column.
- Cuando se encuentra \n, increment line y resetea column a 1.

Cada token almacena la línea y columna donde comenzó el lexema.

Esto permite que el parser genere mensajes de error precisos con ubicación del problema.

6. Caracteristicas especiales

6.1 Operadores especiales DIV y MOD

El lexer implementa un comportamiento especial para DIV y MOD:

- Si aparecen en mayúsculas (DIV, MOD), son operadores de división/módulo entero.
- Si aparecen en minúsculas (div, mod), son tratados como identificadores.
- Esta distinción se implementa en identifierScanner verificando si la palabra clave
  está en el mapa KEYWORDS con capitalización exacta.

6.2 Nocion de Token Interface

Cada token es una estructura con campos:

```
interface Token {
  type: TokenType;
  lexeme: string;          // Texto original del token
  literal: string|number|boolean|null;  // Valor interpretado
  line: number;
  column: number;
}
```

- type: Clasificación del token.
- lexeme: Representación textual exacta en el código.
- literal: Valor computado (número para Number, string para String, null para otros).
- line, column: Ubicación en el código fuente.

7. Observacion de arquitectura

La arquitectura del lexer demuestra varios principios de buen diseño:

- Separación clara entre escaneo (lexer.ts), tipos (tokenTypes.ts), reconocimiento (scanners/),
  y utilidades (utils/).
- Patrón Strategy para scanners especializados: cada categoría de token tiene su lógica aislada.
- Inyección de dependencias mediante parámetro state: scanners no acceden directamente a
  posición del lexer, permiten testeo.
- Centralización de reglas: tokenRules.ts mantiene palabras clave y reglas especiales en un lugar.
- Manejo uniforme de ubicación: cada token porta su línea y columna para diagnósticos precisos.
- Flujo claro: Lexer.tokenize() → scanToken() → scanner especializado → addToken().

Esta arquitectura facilita:

- Agregar nuevos tipos de tokens sin tocar lexer.ts.
- Modificar reglas de palabras clave solo en tokenRules.ts.
- Testear escanners especializados de forma aislada.
- Agregar caracteres especiales o escape sequences con cambios mínimos.
