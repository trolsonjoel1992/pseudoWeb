Descripcion detallada de la carpeta interpreter

1. Proposito general

La carpeta src/interpreter contiene el nucleo de ejecucion de pseudoWeb. Toma el AST producido por el parser y lo convierte en comportamiento real: administra el entorno, evalua expresiones, ejecuta sentencias, invoca funciones y procedimientos, y aplica validaciones de tipos y seguridad.

La implementacion esta dividida en modulos pequenos para separar responsabilidades y facilitar pruebas y mantenimiento.

3. Descripcion de los modulos

3.1 orchestrator/evaluator.ts

Contiene la clase Evaluator. Es la fachada principal del interprete y coordina inicializacion, registro de Ambiente, evaluacion del Proceso y ejecucion de sentencias.

3.2 orchestrator/statementDispatcher.ts

Desvia cada sentencia al evaluador especializado correspondiente. Centraliza el patron de despacho para Si, Mientras, Para, Repetir, Segun, Leer y Escribir.

3.3 orchestrator/statementHandlerRegistry.ts

Mantiene el registro de handlers de sentencias. El dispatcher consulta este registro para resolver de forma declarativa la evaluacion especializada.

3.4 builtins/math.ts

Implementa funciones matematicas integradas como REDOND. Estas funciones se registran durante la inicializacion del interprete.

3.5 builtins/registry.ts

Mantiene el registro de funciones integradas y permite consultar si un nombre corresponde a un builtin.

3.6 callables/callableRegistry.ts

Registra funciones y procedimientos definidos por el usuario dentro del programa. Separa el indice de callables por tipo para resolver colisiones y consultas rapidas.

3.7 callables/callableResolver.ts

Resuelve si un nombre corresponde a una funcion o procedimiento, builtin o de usuario.

3.8 callables/callableInvoker.ts

Orquesta la invocacion de funciones y procedimientos, delegando al ejecutor correcto segun la resolucion previa.

3.9 callables/callableExecutor.ts

Ejecuta funciones y procedimientos de usuario en un entorno aislado, valida argumentos y restaura el contexto cuando termina la llamada.

3.10 environment/environment.ts

Representa la tabla de simbolos en tiempo de ejecucion. Guarda valores, tipos y banderas de inmutabilidad, y resuelve busquedas a traves de entornos padre-hijo.

3.11 environment/environmentManager.ts

Administra la pila de entornos activos. Se usa para crear y retirar contextos durante llamadas a funciones y procedimientos.

3.12 evaluators/expressionEvaluator.ts

Evalua expresiones del AST y devuelve valores concretos. Maneja literales, identificadores, agrupaciones, unarios, binarios y llamadas a funciones.

3.13 evaluators/ifEvaluator.ts

Evalua la estructura Si...Entonces...SiNo.

3.14 evaluators/whileEvaluator.ts

Evalua la estructura Mientras.

3.15 evaluators/forEvaluator.ts

Evalua la estructura Para.

3.16 evaluators/doWhileEvaluator.ts

Evalua la estructura Repetir...HastaQue.

3.17 evaluators/switchEvaluator.ts

Evalua la estructura Segun.

3.18 evaluators/ioEvaluator.ts

Aisla la logica de Leer y Escribir.

3.19 evaluators/loopGuard.ts

Protege contra bucles excesivos o potencialmente infinitos.

3.20 types/evaluatorContext.ts

Define el contrato que consumen los evaluadores especializados para interactuar con entorno, tipos, entrada y salida.

3.21 types/evaluatorContextContracts.ts

Define contratos mas especificos para subsets del contexto cuando un evaluador no necesita toda la interfaz completa.

3.22 types/typeChecker.ts

Actua como fachada para validacion y coercion de tipos.

3.23 types/typeValidator.ts

Contiene las reglas de validacion de tipo en tiempo de ejecucion.

3.24 types/typeCoercer.ts

Implementa conversiones controladas de valores cuando la entrada lo permite.

3.25 utils/valueUtils.ts

Agrupa utilidades compartidas para convertir, comparar y presentar valores.

4. Flujo de ejecucion

1. El AST llega al Evaluator.
2. Se inicializan builtins, entorno, manager de entornos, type checker y registro de callables.
3. Se registran las declaraciones del bloque Ambiente.
4. Se ejecuta el bloque Proceso mediante el dispatcher de sentencias.
5. Las expresiones y llamadas se resuelven con el contexto de ejecucion activo.

5. Reglas de dependencia

- orchestrator/ puede importar de todos los demas modulos.
- evaluators/ puede importar de types/, utils/, constants/, environment/, callables/ y builtins/ segun la necesidad.
- callables/ depende de builtins/, environment/, types/ y constants/.
- environment/ es la capa de estado de ejecucion y no depende de evaluators/.
- types/ y constants/ permanecen aislados.

6. Como extender el interprete

Para agregar una nueva sentencia:

1. Implementar el evaluador en evaluators/.
2. Registrar el handler en orchestrator/statementHandlerRegistry.ts.
3. Conectar el nuevo handler desde orchestrator/statementDispatcher.ts si la clasificacion cambia.

Para agregar una nueva funcion integrada:

1. Implementarla en builtins/.
2. Registrarla en builtins/registry.ts.

Para agregar una nueva regla de tipos:

1. Actualizar types/typeValidator.ts, types/typeCoercer.ts o types/typeChecker.ts segun corresponda.
