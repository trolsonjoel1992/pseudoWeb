Descripcion general de la carpeta core/src

1. Proposito general

La carpeta src contiene la API publica y el nucleo funcional del paquete core. Desde aqui se exponen el lexer, el parser, el interpreter y las clases base de error que usa todo el motor de pseudocodigo.

Su objetivo es convertir texto fuente en tokens, tokens en AST y AST en ejecucion real, manteniendo una separacion clara entre analisis lexico, analisis sintactico y evaluacion en tiempo de ejecucion.

2. Estructura general de la carpeta

src/
  errors.ts
  index.ts
  lexer/
  parser/
  interpreter/

3. Descripcion de los modulos principales

3.1 index.ts

Expone la superficie publica del paquete core. Reexporta el Lexer, el Parser, el Evaluator, el Environment y las clases de error para que el resto de la aplicacion consuma una sola entrada.

3.2 errors.ts

Centraliza las clases base de error del dominio: PseudocodeError, LexerError, ParserError, InterpreterError y RuntimeError. Esto unifica el manejo de errores por capa sin mezclar mensajes concretos de cada modulo.

3.3 lexer/

Convierte el codigo fuente en tokens. Incluye orquestacion, scanners, tipos y utilidades para reconocer palabras reservadas, literales, operadores y comentarios.

3.4 parser/

Transforma la secuencia de tokens en un AST estructurado. Organiza el analisis en orquestacion, estado, sintaxis, tipos y utilidades compartidas.

3.5 interpreter/

Ejecuta el AST generado por el parser. Gestiona builtins, callables, entorno, evaluadores especializados y validaciones de tipos y flujo.

4. Flujo general de ejecucion

1. El codigo fuente entra por Lexer.
2. Lexer produce una lista de tokens.
3. Parser consume los tokens y construye un AST.
4. Evaluator interpreta el AST sobre un Environment activo.
5. El resultado final incluye salida, variables y errores con ubicacion.

5. Reglas de dependencia

- index.ts puede reexportar desde cualquier submodulo.
- lexer/ no depende de parser/ ni interpreter/.
- parser/ depende de lexer/ para leer tokens, pero no de interpreter/.
- interpreter/ depende de parser/ para entender el AST y de errors.ts para reportar fallos de ejecucion.
- errors.ts se mantiene como capa comun de clases de error, sin contener la logica de cada modulo.

6. Como extender core/src

Para agregar una capacidad nueva, primero se identifica la capa responsable.

- Si cambia la forma de leer texto, se trabaja en lexer/.
- Si cambia la estructura del lenguaje, se trabaja en parser/.
- Si cambia la semantica de ejecucion, se trabaja en interpreter/.
- Si cambia el contrato de error comun, se actualiza errors.ts y index.ts.

7. Idea de arquitectura

core/src funciona como un pipeline modular de tres etapas con un punto de entrada comun. Esta separacion facilita pruebas, mantenimiento y extension sin acoplar el analisis lexical, el parseo y la ejecucion.
