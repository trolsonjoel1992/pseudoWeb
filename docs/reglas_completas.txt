ALCANCE REAL DEL LENGUAJE PSEUDOWEB (ESTADO ACTUAL)


1) ESTRUCTURA OBLIGATORIA DEL PROGRAMA

Un programa ejecutable debe tener esta estructura:

Accion <nombre> : ES
Ambiente
    // declaraciones
Proceso
    // sentencias
FinAccion

Reglas vigentes:
- Accion <identificador> : ES es obligatorio.
- Ambiente es obligatorio.
- Proceso es obligatorio.
- FinAccion es obligatorio.
- El parser no acepta ejecutar fragmentos sueltos fuera de esta estructura.

2) LEXER (TOKENIZACION) IMPLEMENTADO

2.1 Palabras reservadas reconocidas (case-insensitive, salvo donde se indique)
- Control de programa: Accion, FinAccion, Ambiente, Proceso, ES
- Condicionales y bucles: Si, SiNo, FinSi, Mientras, FinMientras, Para, FinPara, Repetir, HastaQue, Hasta, Hacer, Segun, Otro, FinSegun
- IO: Leer, Escribir
- Subrutinas: Funcion, FinFuncion, Procedimiento, FinProcedimiento
- Tipos/literales: Entero, Real, Caracter, Alfanumerico, Logico, Verdadero, Falso
- Operadores logicos por palabra: Y, O, No
- Operadores aritmeticos por palabra: DIV, MOD (solo mayusculas exactas)

2.2 Operadores y signos soportados
- Asignacion: :=
- Aritmeticos: +, -, *, /, **, DIV, MOD
- Comparacion: =, <>, <, >, <=, >=
- Delimitadores: (, ), :, ,, ;
- Rango ..: tokenizado; en sintaxis de Para esta prohibido (solo Hasta).

2.3 Literales y texto
- Enteros y reales numericos.
- Cadenas con comillas dobles: token Alfanumerico.
- Cadenas con comillas simples: token Caracter.
- Escapes soportados: \n, \t, \r, \\, \' y \".

2.4 Comentarios y separadores
- Comentario de linea: // ...
- Comentario de bloque: /* ... */
- Separadores de sentencias: salto de linea y ;

2.5 Errores lexicos actuales
- Caracter no reconocido -> LexerError con linea/columna.
- Comentario sin cerrar -> LexerError.
- Cadena sin cerrar -> LexerError.

3) AMBIENTE: DECLARACIONES Y ORDEN

3.1 Orden obligatorio implementado
Dentro de Ambiente el parser exige:
1. Constantes
2. Variables
3. Funciones y procedimientos

Si se rompe ese orden, se lanza ParserError.

3.2 Declaraciones soportadas hoy
- Constantes:
    NOMBRE = <literal>
- Variables:
    a, b : Entero
    nombre : Alfanumerico
    alias : AN(20)
- Funciones y procedimientos:
    Funcion suma(a : Entero, b : Entero) : Entero
    Procedimiento mostrar(valor : Entero)

3.3 Tipos soportados actualmente
- Entero
- Real
- Caracter
- Alfanumerico
- Logico
- AN(n) (alfanumerico con longitud maxima n > 0)

3.4 Chequeos semanticos de analisis (Parser)
- Redeclaraciones en el mismo alcance: rechazadas.
- Shadowing en alcance local de subrutinas contra alcance externo: rechazado.
- Palabras reservadas como identificadores: rechazadas por el lexer (no llegan como Identificador).

4) PROCESO: SENTENCIAS SOPORTADAS HOY

4.1 Declaracion de variable en Proceso
- No permitido. Solo en Ambiente.

4.2 Asignacion
- Sintaxis: <identificador> := <expresion>
- La variable debe estar declarada previamente.
- No hay creacion implicita.
- No se puede reasignar una constante.

4.3 Entrada / Salida
- Leer(x)
- Leer(a, b, c)
- Escribir(expr)
- Escribir(expr1, expr2, ...)
- Escribir concatena con un espacio entre argumentos.

4.4 Condicional
- Si <condicion> Entonces ... [SiNo ...] FinSi
- Entonces obligatorio.

4.5 Mientras
- Mientras <condicion> Hacer ... FinMientras
- Hacer obligatorio.
- Limite de seguridad: 10,000 iteraciones.

4.6 Para
- Para i := <inicio> Hasta <fin> [, <paso>] Hacer ... FinPara
- Solo Hasta como separador.
- Paso opcional; por defecto 1 o -1 segun direccion.
- Paso 0 -> RuntimeError.
- Limite de seguridad: 10,000 iteraciones.

4.7 Repetir
- Repetir ... HastaQue <condicion>
- Limite de seguridad: 10,000 iteraciones.

4.8 Segun
Sintaxis valida:
- Segun <expr> Hacer
      <valor> : <sentencias>
      > <expr> : <sentencias>
      < <expr> : <sentencias>
      >= <expr> : <sentencias>
      <= <expr> : <sentencias>
      Otro : <sentencias>
  FinSegun

Reglas de compatibilidad:
- Casos exactos: tipo del caso debe coincidir con el tipo de la expresion base.
- Casos comparativos (<, >, <=, >=): solo numericos.

5) EXPRESIONES SOPORTADAS

5.1 Operadores
- Aritmeticos: +, -, *, /, **, DIV, MOD
- Comparacion: =, <>, <, >, <=, >=
- Logicos: Y, O, No
- Funciones: REDOND(x)

5.2 Precedencia implementada
1. O
2. Y
3. Igual / Distinto
4. Comparacion (<, <=, >, >=)
5. Suma / Resta
6. Multiplicacion / Division / DIV / MOD
7. Potencia (**), asociativa a derecha
8. Unarios: - y No
9. Primarios: literal, identificador, llamada de funcion, (expresion)

6) SEMANTICA Y RUNTIME ACTUALES

6.1 Inicializacion
- Variables declaradas se inicializan con null.
- null representa ausencia de valor.
- Usar null en operaciones o condiciones genera RuntimeError.
- Constantes se cargan con su valor inicial y son inmutables.

6.2 Validacion de tipos en Leer
- Entero: entero valido.
- Real: numero real valido.
- Caracter: string de longitud 1.
- Alfanumerico: string.
- AN(n): string de longitud <= n.
- Logico: boolean o string true/false/verdadero/falso.

6.3 Validacion estricta de tipos en operaciones
- Operaciones aritmeticas requieren numericos.
- No hay conversion implicita string->numero en operaciones.
- La concatenacion flexible solo existe en Escribir.

6.4 Errores de runtime implementados
- Division por cero (/), DIV por cero, MOD por cero.
- Paso cero en Para.
- Limites de seguridad excedidos en Mientras/Para/Repetir.
- Variable no declarada en asignacion o Leer.
- Reasignacion de constante.
- Incompatibilidad de tipos en asignacion, parametros, retorno y AN(n).
- Uso de procedimiento en expresion o funcion como sentencia de procedimiento de forma invalida.

7) FUNCIONES Y PROCEDIMIENTOS

7.1 Parser
- Parsea declaraciones de Funcion y Procedimiento en Ambiente.
- Parsea parametros tipados (sin &).
- Parsea Ambiente opcional interno y Proceso interno.
- Parsea llamadas:
  - Funcion en expresiones: resultado := suma(1, 2)
  - Procedimiento como sentencia: mostrar(resultado)

7.2 Interprete
- Ejecuta funciones y procedimientos.
- Crea scope local por invocacion.
- Valida cantidad y tipo de argumentos.
- Implementa retorno por asignacion al nombre de la funcion.
- Soporta REDOND(x) como builtin numerico.

8) QUE RECHAZA EXPLICITAMENTE EL ESTADO ACTUAL

Rechazos de Parser (ParserError):
- Estructura fuera de Accion ... FinAccion.
- Si sin Entonces.
- Mientras sin Hacer.
- Para con .. o HastaQue como separador.
- Declaraciones de variables en Proceso.
- Orden roto en Ambiente.
- Redeclaraciones en el mismo alcance.
- Shadowing local en subrutinas contra alcance externo.

Rechazos de Runtime (RuntimeError):
- Asignacion a variable no declarada.
- Leer de variable no declarada.
- Reasignacion de constante.
- Incompatibilidad de tipos (incluye AN(n), parametros, retorno).
- Uso de null en operaciones/condiciones.
- Incompatibilidad de tipos en Segun.
- Bucles infinitos por limite de seguridad.

9) EJEMPLO MINIMO QUE DEBE EJECUTAR

Accion ej1 : ES
Ambiente
    num : Entero
Proceso
    num := 5
    Escribir(num)
FinAccion

Salida esperada: 5

10) PENDIENTES (BRECHA ACTUAL)

Pendientes reales para fases futuras:
1. Parametros por referencia (&).
2. Politica de overflow/underflow explicita para Entero.
3. Mejoras de semantica avanzada (por ejemplo, reglas adicionales de compatibilidad entre tipos para casos mas complejos).
4. Ampliacion de builtins numericos adicionales (si se requiere mas alla de REDOND).
 
builtins faltantes 
Matemáticas: ABS, TRUNC, CEIL, FLOOR, SQRT, MAX, MIN, POTENCIA si no querés usar operador
Texto: LONGITUD, MAYUSC, MINUSC, SUBCADENA, CONCATENAR, REEMPLAZAR
Conversión: A_ENTERO, A_REAL, A_TEXTO, A_LOGICO
Lógica auxiliar: ES_NUMERO, ES_TEXTO, ES_BOOLEANO
Fecha/hora si el lenguaje lo necesita: AHORA, FECHA, HORA

/**
 * Interpreter Logger
 * 
 * Centralized, injectable logging system for debugging interpreter execution.
 * Supports different levels (debug, warn, error) and environments (dev, test, prod).
 */

export interface InterpreterLogger {
  debug(message: string, data?: unknown): void
  warn(message: string, data?: unknown): void
  error(message: string, error?: Error): void
}

/**
 * Console-based logger
 * Respects NODE_ENV to only log in development
 */
export class ConsoleLogger implements InterpreterLogger {
  constructor(private readonly prefix = '[Interpreter]') {}

  public debug(message: string, data?: unknown): void {
    if (process.env.NODE_ENV === 'development' || process.env.NODE_ENV === 'test') {
      // eslint-disable-next-line no-console
      console.debug(`${this.prefix} ${message}`, data ?? '')
    }
  }

  public warn(message: string, data?: unknown): void {
    // eslint-disable-next-line no-console
    console.warn(`${this.prefix} ${message}`, data ?? '')
  }

  public error(message: string, error?: Error): void {
    // eslint-disable-next-line no-console
    console.error(`${this.prefix} ${message}`, error ?? '')
  }
}

/**
 * Null logger for tests or silent mode
 * Implements InterpreterLogger but does nothing (no-op)
 */
export class NullLogger implements InterpreterLogger {
  public debug(): void {}
  public warn(): void {}
  public error(): void {}
}
