Problemas y observaciones
1. scanToken() no debería vivir en LexerStateImpl
Este es el problema más importante. LexerStateImpl debería ser solo estado: peek, advance, addToken, sliceLexeme. La lógica de dispatch (if char === '"', if isDigit, if isAlpha...) es orquestación, no estado.
Hoy LexerStateImpl hace dos cosas: mantiene el estado del cursor Y decide qué scanner invocar. Eso viola el mismo principio que motivó la reestructuración. scanToken() debería estar en orchestrator/lexer.ts dentro de la clase Lexer.
ts// lexerState.ts — solo estado
export class LexerStateImpl implements LexerContext { ... }

// lexer.ts — orquestación
export class Lexer {
  private state: LexerStateImpl

  public tokenize(): Token[] {
    while (!this.state.isAtEnd()) {
      this.state.markStart()
      this.scanToken()
    }
    // ...
  }

  private scanToken(): void {
    const char = this.state.peek()
    if (isDigit(char)) { scanNumberToken(this.state); return }
    // ...
  }
}

2. line y column son public cuando deberían ser readonly
tspublic line = 1
public column = 1
Cualquier código externo puede mutar state.line = 99. Deberían ser:
tsget line(): number { return this._line }
get column(): number { return this._column }
private _line = 1
private _column = 1
O bien exponerse solo a través de LexerContext donde son readonly.

3. asContext() tiene un bug de captura de línea/columna
tsprivate asContext(): LexerContext {
  return {
    line: this.line,   // ← captura el valor en este momento
    column: this.column,
    ...
  }
}
line y column son primitivos: se copian por valor al momento de crear el objeto. Si advance() actualiza this.line después, el objeto context que recibió el scanner sigue reportando el valor viejo.
La corrección es usar getters:
tsprivate asContext(): LexerContext {
  return {
    get line() { return self.line },
    get column() { return self.column },
    peek: this.peek.bind(this),
    // ...
  }
}
O simplemente pasar this directamente si LexerStateImpl implementa LexerContext completo — que ya lo hace.

4. Los scanners reciben objetos anónimos en lugar de LexerContext
tsscanStringToken({
  quote: char,
  line: this.line,      // mismo bug: valor capturado
  column: this.column,  // mismo bug
  isAtEnd: this.isAtEnd.bind(this),
  peek: this.peek.bind(this),
  ...
})
Si los scanners ya aceptan ScannerContext, lo correcto es pasar this.asContext() (o this) más los parámetros extra, no reconstruir el objeto manualmente en cada llamada.
tsscanStringToken(this.asContext(), char)
scanNumberToken(this.asContext())
scanIdentifierToken(this.asContext())
Esto también elimina la duplicación: line, column, isAtEnd, peek, peekNext, advance, sliceLexeme, addToken se repiten en cada bloque hoy.

5. tokenize() también es responsabilidad de Lexer, no de LexerStateImpl
El estado no debería saber qué es un token EOF ni cuándo termina el programa. Esa es lógica de nivel superior.

6. start no está expuesto por LexerContext
sliceLexeme usa this.start internamente, pero start no se actualiza desde fuera del estado. Falta un método markStart() en la interfaz para que Lexer pueda decirle al estado "empieza un nuevo token aquí":
ts// en LexerContext
markStart(): void

// en LexerStateImpl
markStart(): void {
  this.start = this.current
}
