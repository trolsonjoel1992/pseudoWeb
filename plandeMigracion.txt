================================================================================
PLAN: MIGRACIÓN A MONACO EDITOR CON LENGUAJE CUSTOM — pseudoWeb
================================================================================

OBJETIVO
--------
Reemplazar el textarea estilizado actual por Monaco Editor, con un lenguaje
custom registrado que use el lexer de @pseudoweb/core para resaltado real.
El resultado debe mantener la arquitectura actual (App > CodeEditor) y no
romper el flujo de ejecución en useInterpreter.ts.

ESTADO ACTUAL
-------------
- Editor: textarea con numeración de líneas sincronizada manualmente.
- Atajos: useCodeEditorKeyboard.ts (Tab, Enter con indentación).
- Resaltado: ninguno.
- Dependencia del código: App.tsx mantiene `code` como string y lo pasa
  al hook useInterpreter.ts, que lo entrega al Lexer de @pseudoweb/core.

RESULTADO ESPERADO
------------------
- Monaco Editor reemplaza el textarea en CodeEditor.tsx.
- Un lenguaje "pseudoweb" registrado en Monaco con tokenización propia.
- Resaltado de sintaxis funcional: palabras clave, literales, operadores,
  comentarios, identificadores, errores.
- Atajos de teclado actuales preservados o delegados a Monaco.
- El string de código sigue fluyendo hacia App y useInterpreter sin cambios.
- Eliminación de useCodeEditorKeyboard.ts (Monaco lo reemplaza).
- Eliminación de la lógica manual de numeración de líneas.

================================================================================
FASE 1 — INSTALACIÓN Y SETUP BÁSICO
================================================================================

Paso 1.1 — Instalar dependencia
  npm install @monaco-editor/react

  Nota: @monaco-editor/react es el wrapper oficial para React. Internamente
  carga Monaco desde un CDN o bundle local. Para evitar el CDN en producción,
  configurar el loader para usar el bundle local (ver paso 1.3).

Paso 1.2 — Verificar compatibilidad con Vite
  Monaco usa workers para parsing y LSP. Vite necesita configuración especial.
  En vite.config.ts, agregar:

    import { defineConfig } from 'vite'
    import react from '@vitejs/plugin-react'

    export default defineConfig({
      plugins: [react()],
      optimizeDeps: {
        exclude: ['@monaco-editor/react'],
      },
    })

  Alternativa más robusta: usar el plugin vite-plugin-monaco-editor que
  empaqueta los workers correctamente.

    npm install vite-plugin-monaco-editor --save-dev

  Y en vite.config.ts:

    import monacoEditorPlugin from 'vite-plugin-monaco-editor'

    plugins: [
      react(),
      monacoEditorPlugin({ languageWorkers: ['editorWorkerService'] })
    ]

Paso 1.3 — Configurar loader local (opcional pero recomendado)
  Para evitar dependencia de CDN externo:

    import { loader } from '@monaco-editor/react'
    import * as monaco from 'monaco-editor'
    loader.config({ monaco })

  Agregar esto en main.tsx antes de renderizar App.

================================================================================
FASE 2 — REEMPLAZO DEL COMPONENTE CodeEditor
================================================================================

Paso 2.1 — Nuevo CodeEditor.tsx
  Reemplazar el textarea por el componente Editor de @monaco-editor/react.

  Props que debe recibir CodeEditor (sin cambios en la interfaz hacia App):
    - value: string          → el código actual
    - onChange: (v) => void  → callback cuando el usuario edita
    - onExecute: () => void  → para el botón de ejecutar (no cambia)
    - isExecuting: boolean   → para deshabilitar el botón
    - fontSize: number       → configurable desde la UI

  Estructura básica del componente:

    import Editor, { OnMount } from '@monaco-editor/react'

    const CodeEditor = ({ value, onChange, ... }) => {
      const handleMount: OnMount = (editor, monaco) => {
        // Registrar lenguaje y theme aquí (ver Fase 3)
        registerPseudoWebLanguage(monaco)
        monaco.editor.setTheme('pseudoweb-theme')
      }

      return (
        <Editor
          language="pseudoweb"
          theme="pseudoweb-theme"
          value={value}
          onChange={(v) => onChange(v ?? '')}
          onMount={handleMount}
          options={{
            fontSize,
            fontFamily: 'JetBrains Mono, monospace',
            minimap: { enabled: false },
            scrollBeyondLastLine: false,
            lineNumbers: 'on',
            renderLineHighlight: 'line',
            automaticLayout: true,
            tabSize: 2,
            wordWrap: 'on',
          }}
        />
      )
    }

Paso 2.2 — Eliminar useCodeEditorKeyboard.ts
  Monaco maneja Tab, Enter con indentación y todos los atajos estándar
  de forma nativa. El hook ya no es necesario.

  Si existían atajos custom (ej: Ctrl+Enter para ejecutar), agregarlos
  en el callback onMount via editor.addCommand:

    editor.addCommand(
      monaco.KeyMod.CtrlCmd | monaco.KeyCode.Enter,
      () => onExecute()
    )

Paso 2.3 — Eliminar lógica de numeración de líneas
  Monaco la maneja internamente. Borrar el contenedor del gutter y el
  código de sincronización de scroll del CodeEditor anterior.

Paso 2.4 — Botones de fontSize
  Mantener los botones de aumentar/reducir fuente. Ahora solo deben
  actualizar el estado fontSize en App, que se pasa como prop a Monaco.
  Monaco acepta fontSize dinámico via options.

FASE 3 — REGISTRO DEL LENGUAJE PSEUDOWEB EN MONACO
================================================================================

Este es el paso central. Monaco permite definir lenguajes custom usando
Monarch (su sistema de tokenización declarativo).

Paso 3.1 — Crear archivo de registro del lenguaje
  Nuevo archivo: src/monaco/pseudoweb-language.ts

  Este archivo exporta una función:
    export function registerPseudoWebLanguage(monaco: Monaco): void

  Dentro de esa función:

  A) Registrar el lenguaje:
    monaco.languages.register({ id: 'pseudoweb' })

  B) Definir los tokens (tokenizer Monarch):
    monaco.languages.setMonarchTokensProvider('pseudoweb', {
      keywords: [ ... ],       // palabras clave del lenguaje
      typeKeywords: [ ... ],    // tipos si los hay
      operators: [ ... ],
      tokenizer: {
        root: [ ... ]          // reglas de tokenización
      }
    })

  C) Definir autocompletado básico (opcional en esta fase):
    monaco.languages.registerCompletionItemProvider('pseudoweb', { ... })

Paso 3.2 — Identificar tokens desde el Lexer de @pseudoweb/core
  El Lexer ya clasifica los tokens del lenguaje. Revisar los tipos de
  token que produce (ej: KEYWORD, IDENTIFIER, NUMBER, STRING, OPERATOR,
  COMMENT, etc.) y mapearlos a los tipos de Monaco:

    Tipo pseudoweb → Tipo Monaco
    ─────────────────────────────
    KEYWORD        → keyword
    IDENTIFIER     → identifier
    NUMBER         → number
    STRING         → string
    COMMENT        → comment
    OPERATOR       → operator
    PUNCTUATION    → delimiter
    BOOLEAN        → keyword.constant (o constant)
    NULL/NIL       → keyword.null
    ERROR/UNKNOWN  → invalid

  Esta tabla depende de los TokenType definidos en @pseudoweb/core.
  Revisarlos antes de escribir el tokenizador Monarch.

Paso 3.3 — Escribir el tokenizador Monarch
  Monarch trabaja con reglas de regex secuenciales. Ejemplo estructural:

    tokenizer: {
      root: [
        // Comentarios (si el lenguaje los tiene)
        [/\/\/.*$/, 'comment'],
        [/\/\*/, 'comment', '@blockComment'],

        // Strings
        [/"/, 'string', '@doubleString'],
        [/'/, 'string', '@singleString'],

        // Números
        [/\d+\.\d+/, 'number.float'],
        [/\d+/, 'number'],

        // Palabras clave vs identificadores
        [/[a-zA-ZáéíóúÁÉÍÓÚñÑ_][\w]*/, {
          cases: {
            '@keywords': 'keyword',
            '@typeKeywords': 'type',
            'verdadero|falso': 'keyword.constant',
            'nulo': 'keyword.null',
            '@default': 'identifier',
          }
        }],

        // Operadores
        [/[+\-*/=<>!&|]+/, 'operator'],

        // Delimitadores
        [/[{}()\[\]]/, 'delimiter.bracket'],
        [/[,;.]/, 'delimiter'],
      ],
      // Estados para strings y comentarios multilinea...
    }

  IMPORTANTE: Si el lenguaje usa palabras clave en español (escribir,
  leer, si, sino, mientras, para, funcion, retornar, etc.), incluirlas
  en el array keywords. Monarch hace el match case-sensitive por defecto.

Paso 3.4 — Crear el theme visual
  Nuevo archivo: src/monaco/pseudoweb-theme.ts

  Define el tema con colores coherentes con la paleta actual de la app.
  Monaco acepta temas en formato IStandaloneThemeData:

    export const pseudoWebTheme = {
      base: 'vs-dark',          // o 'vs' para tema claro
      inherit: true,
      rules: [
        { token: 'keyword',          foreground: 'C792EA' },
        { token: 'keyword.constant', foreground: 'FF9D00' },
        { token: 'string',           foreground: 'C3E88D' },
        { token: 'number',           foreground: 'F78C6C' },
        { token: 'comment',          foreground: '546E7A', fontStyle: 'italic' },
        { token: 'operator',         foreground: '89DDFF' },
        { token: 'identifier',       foreground: 'EEFFFF' },
        { token: 'type',             foreground: 'FFCB6B' },
        { token: 'invalid',          foreground: 'FF5370', fontStyle: 'underline' },
        { token: 'delimiter.bracket',foreground: '89DDFF' },
      ],
      colors: {
        'editor.background':          '#1a1a2e',   // ajustar al fondo actual
        'editor.foreground':          '#EEFFFF',
        'editor.lineHighlightBackground': '#ffffff08',
        'editorLineNumber.foreground':    '#3d3d5c',
        'editorLineNumber.activeForeground': '#89DDFF',
        'editorCursor.foreground':    '#FFCC00',
        'editor.selectionBackground': '#2d4a6e',
      }
    }

  Registrar el theme en registerPseudoWebLanguage antes de setTheme:
    monaco.editor.defineTheme('pseudoweb-theme', pseudoWebTheme)

FASE 4 — MARCADO DE ERRORES EN EL EDITOR
================================================================================

Monaco tiene un sistema de decoraciones y markers que permite subrayar
líneas o rangos con errores, similar a un IDE real.

Paso 4.1 — Exponer referencia al editor
  Guardar la instancia del editor en un ref desde onMount:

    const editorRef = useRef<editor.IStandaloneCodeEditor | null>(null)
    const handleMount: OnMount = (ed) => { editorRef.current = ed }

Paso 4.2 — Actualizar markers cuando hay errores
  Cuando useInterpreter devuelva un error con línea, usar:

    monaco.editor.setModelMarkers(
      editorRef.current.getModel(),
      'pseudoweb',
      [{
        startLineNumber: error.line,
        endLineNumber: error.line,
        startColumn: 1,
        endColumn: 999,
        message: error.message,
        severity: monaco.MarkerSeverity.Error,
      }]
    )

  Limpiar los markers al ejecutar de nuevo:
    monaco.editor.setModelMarkers(model, 'pseudoweb', [])

Paso 4.3 — Integración con App.tsx
  App ya observa el resultado de ejecución y redirige a la vista de errores.
  Agregar una llamada a la función de marcado cuando el resultado es fallo.
  Pasar una callback desde CodeEditor o usar un ref expuesto hacia arriba.

FASE 5 — LIMPIEZA Y AJUSTES FINALES
================================================================================

Paso 5.1 — Remover archivos obsoletos
  - Borrar o vaciar useCodeEditorKeyboard.ts.
  - Limpiar el markup de numeración de líneas en CodeEditor.tsx.
  - Revisar que App.tsx no pase props que CodeEditor ya no consume.

Paso 5.2 — Responsive con Monaco
  Monaco requiere que su contenedor tenga dimensiones definidas.
  Usar automaticLayout: true en las options (ya incluido en paso 2.1).
  El contenedor padre debe tener height explícito (no solo min-height).
  En mobile, asegurarse de que el drawer no corte el editor con overflow hidden.

Paso 5.3 — Font loading
  JetBrains Mono ya está en el proyecto. Monaco necesita que la fuente
  esté cargada antes de renderizar. Verificar que el import CSS de la
  fuente esté en index.css o main.tsx antes del montaje de Monaco.

Paso 5.4 — Pruebas de integración
  - Escribir código válido → verificar resaltado correcto por tipo de token.
  - Escribir código con error de runtime → verificar marker en línea.
  - Ejecutar → verificar que el string llega intacto a useInterpreter.
  - Resize de ventana → verificar que Monaco se redimensiona sin romperse.
  - Mobile → verificar que el teclado virtual no colapsa el editor.

================================================================================
RIESGOS Y CONSIDERACIONES
================================================================================

1. BUNDLE SIZE
   Monaco agrega ~2-4 MB al bundle. Si el proyecto se sirve sin CDN,
   configurar code splitting para que Monaco cargue lazy. El wrapper
   @monaco-editor/react hace esto por defecto (carga async).

2. WORKERS EN VITE
   El error más común al integrar Monaco con Vite son los workers rotos.
   Si aparecen errores de "Cannot use import statement in worker", usar
   vite-plugin-monaco-editor (paso 1.2) o configurar worker manualmente.

3. MONARCH vs LEXER REAL
   Monarch es un tokenizador regex, no semántico. Puede haber diferencias
   entre lo que Monaco resalta y lo que el Lexer de @pseudoweb/core clasifica
   en casos edge (ej: operadores sobrecargados, literales especiales).
   Priorizar coherencia visual sobre exactitud semántica en esta fase.
   Un LSP completo integrado con el core sería una mejora futura.

4. TEMA CLARO/OSCURO
   Si la app soporta toggle de tema, registrar dos themes en Monaco
   ('pseudoweb-dark' y 'pseudoweb-light') y cambiar con
   monaco.editor.setTheme() al togglear.

5. ACCESIBILIDAD
   Monaco tiene soporte de accesibilidad nativo (screen readers, navegación
   por teclado). Verificar que el tab index y el foco no rompan el flujo
   del sidebar y los botones de la app.
